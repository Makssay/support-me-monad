# Support Me: ручная проверка

Дата: 10 октября 2026. Приложение: http://127.0.0.1:3001/. Сеть: Monad Testnet (10143).

## Подготовка

- Три отдельных профиля браузера: A — автор, B — участник с синей галочкой X, C — участник без галочки. Входи в разные X-аккаунты. Вкладки одного браузерного профиля могут делить сессию.
- Используй маленькую награду 0,01 MON, одно призовое место и «Быстрый тест — каждый этап 5 минут». Общая сумма включает награды, фиксированную комиссию и технические резервы; смотри итог перед подписью.
- На testnet комиссии создания: 0,20 MON базовая; 0,50 MON с X API/галочкой или top-holder snapshot; 2 MON с AI. Комбинации используют старший тариф. Pyth, технический резерв и газ отдельно. Награда в ERC-20 не заменяет MON для технических расходов.
- Запиши ID каждого задания и роли аккаунтов. Для проверки автоматики сервер должен оставаться запущенным; исполнитель должен иметь MON на газ. Callback Pyth может прийти позже таймера.

## 1. Главный сценарий: рафл для аккаунтов с синей галочкой

1. A: Создать задание → Рафл сообщества → 0,01 MON → 1 победитель → быстрый тест.
2. Детали → Кто может участвовать? → Только X-аккаунты с синей галочкой. Discord и NFT отключены, AI выключен.
3. Заполни название, описание и условия. Проверь итоговую сумму. Опубликуй и профинансируй.
4. На странице задания должны быть видны требование галочки, награда и дедлайн. Условия после финансирования не редактируются.
5. C: открой участие. До проверки кнопка вступления заблокирована. Проверка должна сообщить об отсутствии галочки; заявки в списке нет.
6. B: проверь доступ. Подпиши сообщения и транзакцию допуска. После подтверждения доступ разрешён.
7. B: введи имя, прими условия и нажми «Участвовать в рафле сообщества». Отдельная транзакция вступления должна пройти. Проверка допуска сама по себе не является заявкой.
8. Обнови страницу: заявка остаётся. Повторно вступить нельзя. A не может участвовать в собственном задании.
9. Дождись дедлайна. Новые заявки закрыты. При работающем и обеспеченном газом исполнителе розыгрыш запускается автоматически; доступны ручные кнопки запуска и расчёта.
10. Дождись callback Pyth, затем выплаты. С единственным допущенным участником и одним призом B должен получить 0,01 MON.
11. Открой транзакцию в Monadscan: успешный статус, правильный контракт, получатель и сумма. Газ собственных транзакций проверяй отдельно от награды.
12. Открой профиль B: правильный X, рабочая ссылка на него, награда и история. Случайный выигрыш не должен повышать Signal Score за качество работы.

## 2. Рафл реплаев + синяя галочка

1. A: новое задание → категория «Реплаи», режим «Рафл». Укажи публичный исходный пост X. Включи галочку; AI пока выключен. Профинансируй.
2. B: сначала получи допуск по галочке. Затем получи персональный код реплая.
3. Опубликуй прямой ответ на исходный пост с того X-аккаунта, через который вошёл B. Код вставь отдельным словом. Сделай это после получения кода и до дедлайна.
4. Вставь ссылку на ответ → проверь реплай → убедись, что показан настоящий текст → отправь подтверждённую заявку отдельной транзакцией.
5. Повтори выплатный сценарий из пункта 1.
6. В отдельных ещё открытых заданиях проверь ошибки: ссылка на исходный пост; ответ на чужой комментарий; цитата; ответ без кода; ответ с другого X-аккаунта. Они не должны допускаться. Для повторной проверки меняй ссылку; заявка с уже использованным постом не проходит повторно.
7. C: отсутствие галочки не должно позволить обойти допуск даже при правильном реплае.

Внешние пользователи могут отвечать прямо в X. Фильтр ограничивает участие и награды в Support Me.

## 3. Галочка в обычном задании

1. A: категория «Обратная связь» → оплачиваемые отчёты → включи галочку → опубликуй.
2. C не получает допуск и не может зарезервировать место.
3. B проходит допуск, резервирует место, отправляет отчёт до срока доставки.
4. A принимает работу → B получает указанную награду. Проверь профиль, историю и Signal Score.
5. Отдельно создай задание без фильтров: C должен участвовать без проверки галочки.

## 4. NFT / список кошельков

1. A: рафл сообщества → список кошельков организатора. Добавь адрес внешнего кошелька B, отличающийся от его кошелька выплат Support Me.
2. TXT/CSV: одна строка — один адрес; необязательный заголовок `address`. Добавь дубль: счётчик дублей должен сработать. Добавь неправильную строку: продолжение блокируется. Исправь и опубликуй.
3. B: подпиши проверку временным внешним кошельком. Основной кошелёк Support Me не должен поменяться; награда должна прийти на него.
4. Кошелёк вне списка не получает допуск.
5. В другом задании включи и галочку, и список кошельков. Нужны оба условия: галочка без подходящего кошелька и подходящий кошелёк без галочки не подходят.
6. Для проверки реального владения NFT нужна коллекция в текущей сети. В динамическом NFT-рафле переведи NFT после вступления и до финальной проверки: при известном нулевом балансе заявка исключается. Если не осталось подходящих участников — незавершённый рафл возвращает оставшиеся средства автору.

Списки организатора подтверждают контроль адреса, а не владение NFT или позицию в рейтинге. Для top-N нужна подходящая ERC-721 коллекция и полная история RPC; при ничьей отдельный Pyth-розыгрыш оплачивается сразу, даже без публикации задания.

## 5. Discord

В текущем обычном приложении Discord OAuth не настроен: варианты должны быть недоступны с объяснением. Это ожидаемое поведение. Локальные сценарии с фикстурами уже проверены автоматически.

После настройки OAuth отдельно проверить: член сервера проходит, посторонний нет; нужная роль проходит, другая нет; импорт Discord ID сохраняет длинные ID без округления; в комбинированном задании выполняются все условия. Для динамического рафла выход с сервера/потеря роли до финальной проверки исключает заявку; недоступность API приостанавливает весь финальный проход, а не исключает человека молча.

## 6. Остальные режимы и защита средств

Каждый пункт — отдельное задание. Ориентируйся на отображаемые сроки: быстрый режим не означает завершение всей цепочки за пять минут.

- Выбор автора: две заявки, один приз → выбрать победителя → выплата только ему. В новом задании никого не выбирать → после срока выбора оставшиеся призы уходят через случайный выбор.
- Оплачиваемые отчёты: без резерва нельзя сдать работу; с резервом своевременный отчёт можно принять. В отдельном задании автор бездействует → после срока проверки поданная ожидающая работа оплачивается по защитному сценарию.
- Выбранный исполнитель: короткое предложение → выбор автора → резерв награды → полная работа → принятие и выплата. До выбора полная работа не требуется. После своевременной доставки проверить автоматическую выплату при бездействии автора.
- Баг-баунти: воспроизводимый баг по условиям → проверка автором → выплата. Дубликат одного бага не должен получать вторую награду; отклонение требует публичной причины. Здесь нет гарантированной оплаты любого отчёта.
- AI-конкурс: сумма весов ровно 100%, от 1 до 10 критериев; недопустимая сумма блокирует продолжение. После дедлайна AI оценивает по зафиксированным условиям; автор не назначает победителя вручную. Для реплаев/контента X включается X API, текст формы не заменяет реальный пост. Это платная проверка — для ручного теста хватит двух заявок.
- ERC-20: выбирай только поддерживаемый токен текущей сети, проверь адрес/decimals/сумму approve, затем финансирование. Награда выплачивается в выбранном токене; комиссии/Pyth оплачиваются в MON. MON должен остаться на технические расходы.
- Закрытие: задание без участников можно безопасно закрыть. После заявки нельзя произвольно забрать обещанный приз в обход правил режима. Создательская комиссия не возвращается. Проверь раздельно возврат оставшегося призового фонда и технических резервов.

## 7. Интерфейс и сессии

- RU/EN: создание, допуск, ошибки, режимы, сумма и дедлайн читаемы; смена языка не стирает форму.
- Телефон: 320–390 px, форма без горизонтального скролла; кнопки и длинные адреса не вылезают.
- Смена аккаунта: старая заявка/проверка другого участника не переносится в новую форму.
- Обновление страницы: не теряются уже подтверждённые наchain допуск, заявка и выплата.
- Двойной клик: одна транзакция/заявка, без двойной выплаты.
- Отказ от подписи: понятное сообщение, можно повторить; неподтверждённое действие не показывается успешным.

## Уже покрыто автоматически

69 unit/app тестов, 3 community-интеграционных сценария, production build и production browser smoke на шести страницах при 320/390 px. Покрыты невалидный статус, бизнес/государственная галочка, отказ API, лимит расходов, кэш, попытка повторного допуска тем же X, платный сервисный тариф, статический допуск и локальная выплата. Живые профили провайдера проверены; полный новый сценарий с входом реального B через Privy и выплатой на testnet остаётся ручной проверкой.

Не нужно покупать/отменять Premium или специально расходовать баланс API для имитации сбоев — эти случаи покрыты тестами.

## Как прислать баг

ID/ссылка задания; роль A/B/C; режим и фильтры; точные шаги; ожидаемый и фактический результат; текст ошибки; хеш транзакции, если она была; браузер и ширина экрана. Прикладывай только экран приложения; ключи, `.env`, seed и OAuth-токены не отправляй.
